# GlassStream — Project Plan

## Project Goal

I am an individual developer building **GlassStream** for Meta Ray-Ban Display glasses using the **Meta Wearables Device Access Toolkit (DAT) for Android**.

The goal of the first version is deliberately simple:

> **Get data from the glasses into my Android application, and send data back to the glasses.**

I am **not building the ML system yet**. I first want to prove that I can establish a reliable bidirectional connection with the glasses and control the relevant input/output channels.

The desired eventual data flow is:

```text
                 META RAY-BAN DISPLAY
                         │
              ┌──────────┼──────────┐
              │          │          │
           Camera       Mic      Sensors
              │          │
              ▼          ▼
          ┌──────────────────────┐
          │    Android App       │
          │      GlassStream     │
          └──────────┬───────────┘
                     │
              processing/model
                     │
              ┌──────┴──────┐
              ▼             ▼
           Audio         Display
              │             │
              └──────┬──────┘
                     ▼
                 GLASSES
```

# 1. What We Are Actually Trying to Prove

The first milestone is **not AI**.

We want to prove these four things independently.

## A. Camera Input

```text
Glasses camera
      ↓
Meta DAT
      ↓
Android app
      ↓
Receive video frames
```

The Android app should be able to receive frames from the glasses' camera.

Eventually those frames will become input to the model:

```text
Camera
   ↓
Video frames
   ↓
ML model
   ↓
Prediction
```

Initially, we can simply display/log/process the frames to prove that streaming works.

---

## B. Audio Input

Eventually:

```text
Glasses microphone
        ↓
Android
        ↓
Audio stream/data
        ↓
Processing/model
```

The initial goal is simply to establish that audio from the glasses can reach the Android side.

---

## C. Audio Output

Once input works:

```text
Android
   ↓
generated audio
   ↓
glasses
   ↓
speakers
```

For the first test, we do not need an AI model.

We can generate something simple such as:

```text
"Hello from GlassStream"
```

and verify that the sound reaches the glasses.

Later:

```text
ML result
    ↓
Text
    ↓
TTS
    ↓
Audio
    ↓
Glasses speakers
```

---

## D. Display Output

Because these are **Ray-Ban Meta Display glasses**, we also want:

```text
Android
   ↓
DAT Display API
   ↓
Glasses display
```

Initially, the simplest possible test is something like:

```text
GlassStream

CONNECTED
```

Then:

```text
Object detected

PERSON
92%
```

Eventually the display can show information generated by the model.

# 2. Final Architecture

The eventual architecture should look approximately like this:

```text
                         ┌─────────────────────┐
                         │  Ray-Ban Display    │
                         │                     │
                         │ Camera              │
                         │ Microphone           │
                         │ Speakers             │
                         │ Display              │
                         └──────────┬──────────┘
                                    │
                           Meta Wearables DAT
                                    │
                                    ▼
                         ┌─────────────────────┐
                         │     Android         │
                         │     GlassStream     │
                         │                     │
                         │ Device connection   │
                         │ Video receiver      │
                         │ Audio receiver       │
                         │ Audio transmitter   │
                         │ Display controller  │
                         └──────────┬──────────┘
                                    │
                                    ▼
                         ┌─────────────────────┐
                         │ Processing / Model  │
                         │                     │
                         │ CV / AI / logic     │
                         └──────────┬──────────┘
                                    │
                        ┌───────────┴───────────┐
                        ▼                       ▼
                     TTS/audio              Display data
                        │                       │
                        └───────────┬───────────┘
                                    ▼
                              Meta glasses
```

The Android phone is initially the **bridge and compute device**.

The glasses provide the hardware interfaces.

The Android application controls the communication and processing.

The ML model can be introduced later without changing the fundamental glasses connection architecture.

# 14. Stage 11 — Optimize the System

Only after functionality works do we investigate:

## Latency

```text
camera
 ↓
frame
 ↓
processing
 ↓
model
 ↓
output
```

Measure the time between these stages.

## Throughput

Determine how many frames per second can actually be processed.

## Resolution

Determine how much camera data is necessary.

## Model Speed

Determine whether the phone can run the model.

## Network Dependence

Determine whether inference should run:

```text
phone only
```

or:

```text
phone → cloud → phone
```

## Battery

Continuous camera streaming and inference can be expensive.

## Reliability

Test what happens when:

- Bluetooth disconnects
- glasses sleep
- phone loses network
- Meta AI disconnects
- camera stream stops
- model crashes

These are later engineering problems.

   ↓

   ↓

# 18. Progress Log

Follow-the-plan build, one capability at a time, each verified on real hardware
(Ray-Ban Display + Android phone). See the app code under
`app/src/main/java/com/example/glassstream/` (`MainActivity`, `wearables/`).

- **Stage 1 — AndroidManifest** ✅
  Permissions (BLUETOOTH, BLUETOOTH_CONNECT, INTERNET, CAMERA), DAT metadata
  `APPLICATION_ID`/`CLIENT_TOKEN` = `"0"` (Developer Mode — no real credentials needed),
  and the Meta AI callback intent-filter (`glassstream://`). `minSdk` raised to 29
  (required by `mwdat-camera`).

- **Stage 2 — DAT init + Meta AI registration** ✅ (confirmed on device)
  `Wearables.initialize` after Android permissions; observe `registrationState` and
  discovered `devices`; Register/Unregister via the Meta AI app.

- **Stage 3 — Developer Mode + on-glasses DAT app** ✅
  Enabled Developer Mode in Meta AI and installed the on-glasses Device Access Toolkit
  app. Note: the on-glasses install failed at 18% until the **glasses were restarted**,
  after which it completed. (Prereqs: Meta AI ≥ v272, firmware ≥ v125, battery > 10%,
  Wi-Fi on.)

- **Stage 4 — DeviceSession** ✅ (confirmed on device)
  `Wearables.createSession(AutoDeviceSelector())` → `session.start()`; session reaches
  `STARTED`. Connection layer proven.

- **Stage 5 — Camera** ✅ (fully done: photo + live video + on-screen preview)
  - ✅ **Camera input proven**: `capturePhoto()` returns a real image, shown in the app.
  - ✅ **Live video stream working**: `addCamera` + `videoStream` deliver frames
    (~504x896 HEVC).
  - ✅ **5b — live preview on screen**: ported Meta's software `HevcDecoder`
    (`stream/HevcDecoder.kt`) which renders decoded frames straight to an
    `AndroidExternalSurface`; the live camera feed shows on the phone.
  - History: video was blocked ~Sept 8–24, 2026 by a **Ray-Ban Display firmware
    regression** (v128), tracked in Meta issue #178. Fixed by updating to **firmware
    129 + SDK 1.0.0**, then re-pushing developer-mode credentials in Meta AI and
    **re-registering** the app. The SDK dependency was bumped `0.9.0 → 1.0.0`.

- **Stage 6 — Audio input** ✅ (confirmed on device)
  The glasses microphone rides the camera stream: `StreamConfiguration(audioCodec =
  AudioCodec.PCM(RATE_16000, 1))` plus the wearable MICROPHONE permission, then collect
  `stream.audioStream` (16-bit PCM, mono, 16 kHz `AudioFrame`s). The app counts audio
  frames and shows a live peak-level meter that responds to sound. Mic is optional — if
  the grant is denied the stream runs video-only.

- **Stage 7 — Audio output** ✅ (confirmed on device)
  Not a DAT capability — the glasses are a standard **Bluetooth A2DP** speaker. Uses
  Android `TextToSpeech` (USAGE_MEDIA → A2DP) to speak "Hello from GlassStream", which
  routes to the glasses when they're the connected media output. Independent of the DAT
  session. UI also shows the detected Bluetooth output device. This sets up the later
  ML→text→TTS→speakers path.

**Next:** Stage 8 — display output (show text on the Ray-Ban Display via mwdat-display).
